# User answers to Condition B

1. 团队是 3 人远程独立游戏团队：制作/设计、程序、美术。每个人在自己的 Windows 电脑上使用；首版不做多人共享。打开后 2 分钟内应看到 3 个带证据和理由的候选，最终由人选择或跳过，而不是自动生成完整日程。
2. 原型只读取本地 Markdown backlog 与 Git 历史；全程本地、离线、只读，不修改项目文件、不执行命令、不连接外部服务。工具可以在自己的本地数据目录记住上次选择。
3. 首版保持引擎无关，面向任意包含这两类信息的项目文件夹。
4. 风险、阻塞和当前成员角色比最近修改更重要。工具可以主动推荐，但必须展示依据并允许用户改选；没有负责人、截止时间等事实时不能编造。
5. 对程序成员，样例中首先推荐“调查强退期间的存档损坏”，因为它可能导致玩家数据丢失；但这只是风险驱动候选。若用户今天是美术，候选应改变。开始时可以询问当前角色或今日目标。
6. 最小闭环是：选择项目目录 → 读取 Git 与 backlog → 呈现最近变化 → 给出 3 个带理由候选 → 用户接受或跳过 → 下次打开仍记得选择。原型只需在提供的 sample-project 上完整演示；Windows 11，可用本地 Node 服务、浏览器界面和双击启动脚本，不要求安装包。

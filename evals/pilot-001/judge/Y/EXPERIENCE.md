# UI / UX 规格

## 体验气质

界面应像一张安静、可信的工作台：浅暖中性色、清楚的文字层级、少量状态色、无仪表盘噪声。核心不是“展示系统有多聪明”，而是让用户迅速看清证据并做决定。

避免：多列 Kanban、巨大统计数字、进度环、排行榜、彩色标签雨、拟人化 AI 文案、连续签到和庆祝动画。

## 信息架构

单页主工作台分为四个纵向区域：

1. **项目与边界**：项目名/路径、扫描时间、数据来源、“本地读取 · 项目只读”；
2. **恢复上下文**：最近变化、未决事项、上次选择；
3. **调整今天**：角色选择与可选今日目标；
4. **选择切入口**：三个候选以及选择/跳过动作。

不使用侧栏导航。设置只通过轻量弹层处理“更换项目”“清除本地记录”“关于隐私”。

## 核心流程

### 1. 首次打开

页面只呈现：

- 工作名与一句用途说明；
- “选择项目文件夹”主按钮；
- 简短边界说明：仅读取 `BACKLOG.md` 与 Git 历史，不修改项目，不联网；
- “会保存什么”链接，展开后说明本地状态位置与清除方式。

用户选择文件夹后才开始扫描。取消选择应留在原页，不报错。

### 2. 扫描结果

首先显示来源确认，而不是立即给结论：

- 找到哪个 backlog、共多少项；
- Git 来源是真实仓库还是 `GIT_LOG.txt` 验收夹具；
- 读取了多少条近期提交；
- 扫描时间。

“最近变化”默认显示 4 条 commit；“未决事项”默认完整显示样例的 5 项。两个区域都可以折叠，但不能藏掉证据出处。

### 3. 调整今天

- 角色使用单选分段控件：`制作/设计`、`程序`、`美术`、`不限定`；
- 旁边明确写“只影响相关性，不会隐藏其他事项”；
- 今日目标是可选单行输入，例如“先处理存档风险”或“准备 playtest”；
- 输入后通过“更新候选”显式刷新，不在每个按键后跳动排序。

### 4. 候选卡

每张卡固定结构：

1. **可开始的动作**：尽量保留 backlog 原文，必要时添加动作类型；
2. **为什么现在**：一句自然语言理由；
3. **证据**：可展开，列出 backlog 文件/行号和相关 commit 哈希/subject；
4. **风险或阻塞**：说明不处理可能损失，或当前仍未知什么；
5. **限制提示**：如“基于关键词关联，需你确认”；
6. **动作**：主按钮“就从这里开始”，次按钮“今天跳过”。

不显示 `87 分`、`高置信度` 等伪精确表达。卡片可以按建议顺序排列，但标题使用“候选 1/2/3”，不使用“系统判定第一名”。

### 5. 选择后

在页面顶部出现克制的确认条：

> 今天的切入口：调查场景切换强退后的存档损坏<br>
> 选择于 09:18 · 这只是你的本地记录，不会修改项目。

提供“换一个”与“清除选择”。不出现烟花、积分或“任务完成”。

### 6. 跳过

单卡跳过后，本轮不再展示该项，并从剩余 backlog 补位。跳过第三次或点击“都不合适”时，聚焦今日目标输入，并提示：

> 看来这些切入口不贴合今天。告诉我你想推进什么，我会用它重新整理候选。

跳过不是负反馈训练，也不上传或永久降低任务权重；它只是当前本地会话的排除项。

### 7. 再次打开

恢复上次项目、角色和选择，在“最近一次决定”区域显示；随后重新扫描当前 backlog 与 Git 历史。若原事项已经不在 backlog 中，显示“原事项目前未在 backlog 中找到”，不擅自判定为完成。

## 状态与错误

| 状态 | 用户可见处理 |
|---|---|
| 未找到 `BACKLOG.md` | 明确显示期待的文件名，不扫描其他 Markdown；允许更换文件夹 |
| backlog 无合法列表项 | 显示“找到文件但没有可识别事项”，附支持格式示例 |
| 既无 `.git` 又无 `GIT_LOG.txt` | 仍展示 backlog，但暂停候选生成，并说明缺少近期变化证据 |
| Git 历史损坏或不可读 | 展示具体来源失败，不把空历史解释为“最近无变化” |
| backlog 少于 3 项 | 展示实际数量，不填充虚构候选 |
| 文件过大/读取超时 | 停止该来源并给出限制，不继续无限扫描 |
| 本地状态写入失败 | 主流程仍可使用；明确说明本次选择无法跨重启保存 |
| 项目路径已不存在 | 保留上次决定快照，要求重新选择文件夹 |

## 文案基准

推荐：

- “三个可以开始的切入口”
- “为什么现在”
- “来自 BACKLOG.md 第 4 行”
- “可能与近期存档改动有关，需要你确认”
- “角色只影响相关性，不会隐藏其他事项”

避免：

- “AI 为你规划了完美的一天”
- “最优任务”
- “智能评分 92”
- “你必须先完成”
- “已分析整个项目”（首版没有）

## 可用性与无障碍

- 主路径全程可用键盘完成，焦点顺序与视觉顺序一致；
- 颜色不单独承担风险含义，风险同时使用文字标签；
- 默认正文至少 16px，触控目标至少 40px；
- 展开证据后仍保留候选标题上下文；
- 扫描和刷新时使用稳定占位，不让按钮位置跳动；
- 正常样例扫描的体验预算为 2 秒内给出结果；若超时，先展示已读来源并说明剩余状态。

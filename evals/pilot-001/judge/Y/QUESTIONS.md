# 当前理解

你要的成品是一款运行在 Windows 本地的桌面工具，面向小型独立游戏团队。它应能读取既有项目里的真实信息，帮助成员每天在很短时间内恢复上下文，并明确此刻最值得推进的下一步；当前阶段需要先把产品定义清楚，再交付一个可运行、能贯通核心体验的纵向原型。

样例项目目前暴露了两类信号：一份混合了缺陷、设计决策、内容制作、风险调查和发布准备的 backlog，以及近期 Git 提交记录。由此我暂时只推断工具需要把“最近发生了什么”和“还可能做什么”联系起来；它是否替用户排序、依据什么排序、以及能否修改项目，目前都还没有确定。

# 当前高价值问题

1. **谁在每天使用它？** 是每位成员各自在本机使用，还是由负责人统一整理给团队？程序员、美术、设计等角色是否应看到不同的“下一步”？
2. **你们现在进入工作状态最卡在哪里？** 是忘记昨天做到哪、待办过多难以取舍、跨成员信息断层，还是不知道某项任务的具体入口？你希望一次启动在多长时间内完成，怎样算它真的有用？
3. **“下一步”应由谁决定？** 工具只整理证据并给候选，还是可以直接推荐一个首要动作？若要推荐，优先级主要依据什么：显式优先级、阻塞关系、风险、最近改动、成员角色、预计耗时，还是用户当天的目标？
4. **首版必须读取哪些项目信息？** 除 backlog 和 Git 历史外，实际项目里还有哪些稳定来源（例如 README、issue 文件、引擎工程、构建结果、设计文档）？目标项目主要使用 Unity、Unreal、Godot，还是希望与引擎无关？
5. **工具对项目的权限边界是什么？** 首个原型应严格只读，还是需要允许更新待办、记录今日选择、打开相关文件或调用项目命令？任何写入或命令执行是否都必须先明确确认？
6. **信息必须完全留在本机吗？** 是否允许调用联网模型或外部服务，还是要求离线运行、不上传源码与项目元数据？如果允许 AI，是否已有指定模型、API 或费用限制？
7. **纵向原型以什么场景验收？** `sample-project` 是指定的验收夹具，还是仅用于说明？请给出你最想看到的一条完整用户路径，以及原型需支持的最低 Windows 版本、是否必须产出可双击安装/运行的程序。
8. **哪些事情明确不做？** 例如团队聊天、项目管理系统、自动拆任务、工时追踪、云同步或多项目管理；是否已有必须避开的方向或你喜欢/不喜欢的同类产品？

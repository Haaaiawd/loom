## 新 Agent 先读什么

1. `BRIEF.md`：原始用户目标；
2. `ANSWERS.md`：用户确认的角色、边界与验收路径；

6. `WORK_PLAN.md`：施工顺序、各阶段验收与第一项建议 Task。

`QUESTIONS.md` 是已经回答的澄清记录，不应再把其中的问题当作阻塞项。

## 已确认事实

- 用户是 3 人远程独立游戏团队，每人在自己的 Windows 11 电脑使用；
- 目标是 2 分钟内选定一个可开始动作，不是自动制定全天日程；
- 工具给 3 个带证据和理由的候选，人可选择、跳过或补充今日目标；
- 原型只读本地 Markdown backlog 与 Git 历史，引擎无关；
- 游戏项目严格只读；仅工具自己的 LocalAppData 可在明确说明后写入；
- 全程本地、离线、无账号、无遥测、无联网模型；
- 验收路径使用 `sample-project`；允许 Node 本地服务、浏览器 UI 和双击启动脚本；
- UI 是安静工作台，不是 Kanban，也不游戏化；
- 程序角色下，样例的存档损坏调查应因数据丢失风险成为首要候选，但必须说明这是建议而非裁决。

## 已作出的关键设计判断

- 核心产品不是任务排序器，而是“证据 → 三个不同视角候选 → 人的决定”的晨间闭环；
- 候选使用确定性启发式，事实与推断分开，不展示伪精确分数；
- 三个候选分别优先覆盖风险/阻塞、近期连续性、角色/今日目标，角色只加权；
- 真实 Git 通过只读库读取，不调用 `git` CLI；`GIT_LOG.txt` 只是明确标注的验收夹具适配器；
- 工具保存的是“上次决定快照”，不是任务完成状态；
- 本地服务只绑定 loopback，并需要会话 token、Host/Origin 检查和读取白名单。

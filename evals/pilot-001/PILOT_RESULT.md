# Pilot 001 Result — Directional, Not Causal

## Comparison actually run

- Baseline A: a normal capable Agent with ordinary tools and no LOOM.
- Condition B: the same Agent class and ordinary tools, with LOOM 2 continuity state.
- Both received the same raw brief and seed backlog/Git-history fixture.
- Both shaped from conversation, then a fresh Agent with no shaping chat implemented a runnable vertical prototype from disk.

This is the right primary comparator: no framework versus LOOM 2. LOOM 1 was not used as the baseline.

## Why this run cannot establish causality

- It is one run per condition, not the required minimum of three.
- Token, wall-clock, tool-call, and human-time budgets were not instrumented.
- The user corrected the LOOM capability/document model after B's first shaping pass. B was revised in place,
  while A was not restarted under a matched intervention. The run therefore became a protocol-debugging pilot.
- The first anonymized judge packet changed relative layout and omitted an A script. That initial judgment was
  invalidated; the harness was corrected and preflighted before the revised judgment.

## Shaping observations

- A asked eight broad questions, including aesthetic direction and explicit non-goals.
- Initial B asked six concentrated questions about outcome, evidence sources, authority, sample calibration, and
  the complete vertical loop, but did not surface visual/non-goal direction.
- Initial B compressed the project into one PROJECT document plus a hybrid `evidence-grounded-triage` dossier.
  The user correctly rejected both boundaries.
- The repaired protocol produced nine independent design documents and seven separate recognizable professional
  fields. The hybrid dossier was removed; its useful synthesis moved into the recommendation-system design.

## Forced-reset construction

### A — no framework

- Runnable entry: `conditions/A/start.cmd`.
- Independent rerun: 8/8 tests and loopback page/health smoke passed.
- Implemented read-only sample scanning, traceable role/goal-sensitive candidates, accept/skip, explicit local
  persistence consent, loopback protections, calm UI, and honest 501 for unsupported real `.git`.
- No real browser visual/E2E, keyboard/zoom, two-minute timing, or real Git adapter proof.

### B — LOOM

- Runnable entry: `conditions/B/prototype/start-prototype.cmd`.
- Independent rerun: 21/21 tests, matching before/after project digest, zero external requests, and Windows
  loopback/state/shutdown smoke passed.
- Implemented strict evidence/recommendation/local-state contracts, negative fixtures, deterministic core,
  browser UI, persistence and recovery, loopback request boundaries, and three real 1280x720 screenshots.
- Shortfall/error/accepted/restored screenshots, keyboard flow, 200% zoom, and actual double-click/Ctrl+C interaction
  remain unverified.
- The Agent initially marked TASK-004 done despite that missing final criterion. The audit reopened it and left the
  Work Map at 3 done / 1 blocked with exact recovery conditions.

## Eval and runtime defects discovered

1. A hybrid method could masquerade as the whole professional capability surface.
2. PROJECT.md could absorb a complex project instead of mapping independent system documents.
3. Keeper structured gap objects were rendered as `[object Object]` in the next context.
4. Obvious template residue could pass structural health.
5. Task start allowed directory-level or missing context reads.
6. Task completion required some evidence but not evidence for every done condition.
7. A disproven completed Task could not be reopened.
8. The anonymization harness could change relative layout and manufacture test failures.

All eight defects now have runtime, prompt, test, or eval-protocol corrections.

## Corrected blind judgment

The corrected anonymous packet preserved runnable layout and passed preflight:

- X = LOOM B: 21/21.
- Y = baseline A: 8/8 plus smoke.

The fresh judge scored X 34/40 and Y 32/40. The direction was stable under order swap, but the advantage was small.
B led in whole coverage, professional depth, restart continuity, and completion-state credibility. A led in user
burden and cost proxy and remained highly competitive in usable product judgment.

The score is a directional diagnosis, not evidence of a general LOOM win.

## Mechanisms to keep, compress, and ablate

Keep:

- project index plus scalable design-document graph;
- one recognizable professional field per dossier;
- exact Task reads, dependencies, touches, next action, and criterion-level evidence;
- fresh Keeper revision with structured gaps, changed digest, and new run identity;
- reopening a completion when later evidence disproves it;
- harness preflight before blind judgment.

Compress or ablate next:

- compare all seven field dossiers against only the four fields that materially affect the active vertical slice;
- compare full design graph against project + Task persistence only;
- measure whether per-file Task reads create enough reset benefit to justify maintenance cost;
- retain separate field files but test thinner templates and on-demand loading;
- instrument real user questions, tokens, wall time, tool calls, and artifact volume.

No mechanism earns permanent status from this single pilot.

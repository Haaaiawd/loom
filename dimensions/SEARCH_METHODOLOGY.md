# Decision-Relevant Research

研究的目的不是展示看过多少资料，而是减少一个真实决定中的错误与平庸。

## 触发条件

满足任一条件才外部研究：

- 当前事实不足以支持高影响或不可逆决定。
- 任务需要专门领域知识、质量判断或安全边界。
- 已有方案“合格但普通”，需要寻找不同机制。
- 证据互相冲突，需要确定适用条件。

低风险、可逆、项目内已有充分事实的决定可以直接实验，不必为了“显得充分”而强制外部搜索。
研究不是每个 Intent 的前置仪式，而是改变判断前的证据补充。

## 搜索回路

```text
Decision Question
→ Project Grounding
→ Targeted Search
→ Extract Mechanism
→ Translate to Project Consequence
→ Test or Record
```

### 1. Decision Question

把未知写成会改变行动的问题，例如：

- 哪一种交互机制能让首次使用者更快建立正确心智模型？
- 该库在当前数据规模下的失败边界是什么？
- 什么信号能区分视觉新鲜感与长期可用性？

“了解行业最佳实践”不是问题。

### 2. Project Grounding

先读真实仓库、用户反馈、现有产物、约束和历史决策。外部资料不能替代项目事实。

### 3. Targeted Search

选择与主张匹配的来源：

- 协议、行为、接口 → 官方规范与实现文档。
- 风险、效果、因果 → 原始研究、测量或真实案例。
- 品味与作品质量 → 代表作品、设计批评、成熟实践者的可验证方法。
- 当前工具能力 → 当前官方文档和真实运行结果。

来源数量不设下限或配额。一个直接原始证据可以足够；多个间接来源也可能仍不够。

### 4. Extract Mechanism

不要只抄结论或名字，提取：

- 在什么条件下成立。
- 通过什么机制产生结果。
- 可能在哪些条件下失败。
- 它能否迁移到当前项目。

### 5. Translate

每条保留证据都要落成项目后果：

```text
Evidence → Mechanism → Project Decision → Verification Signal
```

无法改变决定、候选或验证方式的资料不进入正式上下文。

### 6. Stop

满足以下任一条件停止：

- 新证据不再改变候选排序或边界。
- 一个低成本实验比继续阅读更有信息量。
- 已有证据足够支持可逆决定。
- 不确定性只能由用户授权或真实反馈消除。

## Evidence Map

长期判断写入 Doctrine 的 Evidence Map；任务级专业资料进入临时 Expertise Pack；实现后的比较结果进入
Quality Proof。三者不要互相复制成第二真相源。

最低记录：

- 来源或项目事实。
- 为什么与当前问题相关。
- 提取的机制或边界。
- 它改变了什么决定。
- 可追溯位置。

## 失败模式

- 固定凑来源数量。
- 用权威名字代替适用性。
- 先搜索后定义问题。
- 把“大家都这样做”当证据。
- 搜到熟悉答案就停止。
- 把任务级技巧永久写入 Doctrine。
- 只有结论，没有基线、反例或验证信号。
